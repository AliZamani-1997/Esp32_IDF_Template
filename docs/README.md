# مستندات پروژه

این پوشه مرجع طراحی و برنامه‌ریزی پروژه است. هر تصمیم مهمی که می‌گیریم اینجا
ثبت می‌شود تا بعداً معلوم باشد «چرا» این‌طور تصمیم گرفتیم، نه فقط «چی».

> این پوشه از قالب به ارث رسیده و بخش‌های `⬜ TBD` باید برای پروژه‌ی جدید پر
> شوند. بخش‌هایی که قانون‌اند (`CODING_STANDARDS.md` و ساختار لایه‌ها در
> `ARCHITECTURE.md`) از قبل نوشته شده‌اند و معمولاً نیازی به تغییر ندارند.

## فایل‌ها

| فایل | محتوا |
|---|---|
| [`CODING_STANDARDS.md`](CODING_STANDARDS.md) | **اصول کدنویسی — الزامی.** نام‌گذاری، لایه‌بندی، خطا، قالب‌بندی، فهرست ممنوعه‌ها |
| [`ROADMAP.md`](ROADMAP.md) | نقشه‌ی راه، فازها، وضعیت فعلی، سوالات باز |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | معماری چندلایه، سخت‌افزار، کامپوننت‌ها، رابط‌ها |

## چطور از این پوشه استفاده کنیم

1. **هر جلسه‌ی طراحی** با `ROADMAP.md` شروع می‌شود تا ببینیم کجاییم.
2. تصمیم‌های فنی در `ARCHITECTURE.md` ثبت می‌شوند.
3. **قبل از نوشتن کد**، `CODING_STANDARDS.md` را ببین.
4. هر چیزی که هنوز معلوم نیست با نشانه‌ی `⬜ TBD` علامت می‌خورد — این‌ها کارهای باقی‌مانده‌اند.
5. هر چیزی که تأیید شد با ✅ علامت می‌خورد و دلیلش نوشته می‌شود.

## نسخه‌ی عملیاتی (اسکیل‌ها)

این مستندات برای انسان‌اند. نسخه‌ی قابل‌اجرایشان برای ایجنت در
`.workbuddy-ai/skills/` است و **در گیت نگهداری می‌شود**:

| اسکیل | نقش |
|---|---|
| `coding-standards` | خلاصه‌ی الزامی `CODING_STANDARDS.md` — قبل از هر کد |
| `cpp-wrapper-layers` | ساختار چهارلایه، قرارداد RAII، روند افزودن رَپِر |
| `git-commit` | تفکیک کامیت بر اساس موضوع، فرمت پیام، قواعد ایمنی |

> اگر قاعده‌ای عوض شد، **هر دو جا** باید به‌روز شود: سند و اسکیل. سند «چرا» را
> نگه می‌دارد، اسکیل «چطور».

## وضعیت فعلی در یک نگاه

| مورد | مقدار |
|---|---|
| فاز | ۰ (راه‌اندازی قالب) ✅ → فاز ۱ در انتظار نیازمندی‌ها |
| چیپ هدف | با `tools/idf.cmd set-target` انتخاب می‌شود ⬜ |
| معماری | چهار لایه: `core` → `rtos` → `drivers` → `main` ✅ |
| بیلد | سبز ✅ |
| محتوای برنامه | هنوز تعریف نشده ⬜ |

## قواعد مستندسازی

- **مستندات به‌روز باشند، نه کامل.** یک سند کوتاه و درست بهتر از یک سند بلند و قدیمی است.
- **تصمیم‌ها تاریخ‌دار باشند.** بنویس «۱۴۰۵/۰۷/۱۴: انتخاب شد X چون Y».
- **سوالات باز را پنهان نکن.** اگر چیزی معلوم نیست، صریح بنویس.
